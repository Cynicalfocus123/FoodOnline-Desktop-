FoodOnlines Main Frontend + Admin Upload
========================================

ZIP name
- foodonlines-main-live-frontend-upload.zip

Upload location
1. Open cPanel File Manager.
2. Go to public_html/app/
3. Upload foodonlines-main-live-frontend-upload.zip there.
4. Extract the ZIP inside public_html/app/

Route split
- `/` or `/app/` serves `index.html` public frontend.
- `/admin` or `/app/admin` rewrites to `admin.html` admin app.

Files included
- index.html
- admin.html
- assets/
- .htaccess
- DEPLOYMENT-INSTRUCTIONS.txt

Backend files and folders NOT to touch
- Do not overwrite Laravel backend files already serving the API.
- Do not overwrite backend/public/.htaccess
- Do not move or rename backend app/, bootstrap/, config/, database/, routes/, storage/, vendor/, or .env

API base URL config
- Frontend config file: src/lib/runtimeConfig.ts
- Default API base URL: https://foodonlines.com/api/v1

Live endpoints used
- Register: POST /api/v1/auth/register
- Login: POST /api/v1/auth/login
- Current user: GET /api/v1/auth/me
- Logout: POST /api/v1/auth/logout
- Admin users: GET /api/v1/admin/users?account_type=customer|supplier|partner

Quick test
1. Open https://foodonlines.com/app/
2. Confirm homepage title and public frontend load.
3. Open https://foodonlines.com/app/admin
4. Confirm admin app loads separately.
5. Test public register/login.
6. Confirm admin Users tabs show new backend records.

If white screen happens
1. Confirm index.html and admin.html both extracted beside assets/.
2. Confirm assets/ contains both `main-*.js` and `admin-*.js`.
3. Hard refresh browser cache.
4. Check browser Network tab for missing files.

If register/login/admin users fail
1. Confirm Laravel API routes are live.
2. Confirm API base URL still points to https://foodonlines.com/api/v1.
3. Confirm backend CORS/auth/token middleware allow the deployed frontend path.
